任務地圖

同一個 App，三種深度

三個關卡疊在同一個習慣追蹤器上：Advance 建立在 Basic 之上，Master 建立在 Advance 之上。 你可以在 Day 2 的三個實作時段裡，一路往上打，也可以在任何一關停下來， 因為每一關做完，都已經是一個能實際使用的東西。

01
Level 1 · 單檔前端

Basic — 讓它先能動、還要能被看見

目標不是做出完美的介面，而是把「打卡 → 記住 → 算出連續天數 → 畫成看得懂的圖」這條路走通。 因為只有一天時間，手動打卡不可能填滿一整個月，所以「產生示範資料」這顆按鈕 跟打卡功能一樣重要——它讓你在 15 分鐘內，就看到自己做出來的東西「滿版」是什麼樣子。

  • ✓
    新增／刪除習慣輸入名稱就能加入清單，也能移除不想追蹤的項目
  • ✓
    打卡 + localStorage每個習慣旁邊一顆打卡按鈕，資料存在瀏覽器，重整不會不見
  • ✓
    連續天數 Streak顯示目前連續打卡幾天，只要斷一天就從頭算起
  • ✓
    本月熱力圖月曆式格子，打過卡的格子有顏色、深淺代表狀態
  • ✓
    一鍵產生示範資料隨機補上本月打卡紀錄，讓熱力圖立刻有內容可看
為什麼一定要有這顆按鈕：沒有它，你的熱力圖今天就只有一格顏色—— 很難判斷「這個功能到底做對了沒」。假資料讓你能立刻檢查：格子顏色的深淺邏輯對不對、 streak 算法在資料斷掉的地方有沒有正確歸零。
→ 過關標準：重整網頁後，打卡紀錄、streak、熱力圖都還在
02
Level 2 · 前端 + 本地 Server

Advance — 資料要交給後端管，數字要更誠實

Basic 版本的「完成率」其實沒那麼準——如果你只在意「一週三次」的習慣， 跟每天都要打卡的習慣，不應該用同一套標準比較。這一關要讓數字更貼近真實情況， 同時把資料搬出瀏覽器，交給一台你自己架的本地 Server 管理。

  • ✓
    依頻率計算完成率習慣可設定每天／每週幾次，完成率照設定的頻率換算，而不是單純算打卡次數
  • ✓
    習慣分類標籤健康／學習／生活……自訂分類，用顏色快速分辨
  • ✓
    每週回顧報告卡統計這週的完成率與最長連續紀錄，整理成一張可截圖分享的卡片
  • ✓
    前後端分離 + 本地 Server資料改存在你自己架的後端，前端改用 API 讀寫資料
Server 用什麼寫，自己決定：Node.js + Express 或 Python + Flask 都可以—— 挑你和 Bob 討論起來比較順手的那個，資料要存 SQLite 還是 JSON 檔也是你的選擇， 重點是前端不再直接碰資料，一律透過 API。
→ 過關標準：關掉瀏覽器分頁再重開，資料還在後端，不是靠瀏覽器記住的
03
Level 3 · 串接外部世界

Master — 讓它活起來，也讓 Bob 用得到它

最後一關只加兩件事，但兩件事的方向不一樣：一個是讓網頁本身有「活的」內容， 另一個是讓你做出來的整個工具，變成 Bob 自己也能拿來用的東西。

  • ✓
    串接激勵語 API打卡成功或打開網頁時，隨機顯示一句外部 API 回傳的鼓勵語，內容不再是寫死的陣列
  • ✓
    包裝成 MCP Server把「新增習慣」「打卡」「查連續天數」「產生本週報告」這些功能，包裝成 Bob 能直接呼叫的工具
MCP Server 白話一點是什麼：平常你要查自己連續打卡幾天，得打開網頁、找到那個習慣、看數字。 包成 MCP Server 之後，你可以直接跟 Bob 說「幫我查跑步連續幾天了」， Bob 會呼叫你寫的工具去問後端、把答案讀給你聽——你的 App 從「一個網頁」變成「Bob 的一項技能」。
→ 過關標準：跟 Bob 說一句查詢連續天數的話，Bob 能透過你的 MCP Server 答對
起手式

怎麼跟 Bob 開始這場對話

Prompt 要自己想、自己寫——這裡不會給你台詞，只教你跟 Bob 合作的節奏。每一關都照這個順序走一輪。

01

切換 Plan Mode，先講架構不要急著動手

把這一關想做的功能、資料打算怎麼存、畫面大概長什麼樣子，整個跟 Bob 講一遍，讓它先規劃、不要先寫程式

02

把架構過一遍，確認沒問題

看 Bob 整理出來的規劃是不是你要的，覺得哪裡怪就在這階段來回討論、調整——留到寫完才發現方向錯了，成本高很多

03

先讓 Bob 寫測試非必要 · 進階玩法

想挑戰的話，可以先讓 Bob 針對確認好的規劃寫測試案例（TDD），之後每完成一個功能就跑一次測試，確保沒有弄壞前面做好的東西。只是想快點看到成果的話，這步可以跳過

04

切換 Agent Mode，開始動手

架構談好了，才切到 Agent mode 讓 Bob 實際寫程式

05

自己實際打卡測試

連續打好幾天、故意斷一天，看 streak 算得對不對

06

把問題丟回去給 Bob

畫面截圖、錯誤訊息，比空口描述「怪怪的」更容易讓 Bob 抓到問題

這一關真正在練的不是打字速度，是想清楚再開口。 Plan mode 逼你在動手前先把整個系統想過一遍——這跟你自己寫程式時「先想再寫」是同一件事， 只是現在你的隊友換成了 Bob。
技術棧

三關卡，三種技術棧

每一關都在前一關的基礎上加東西，唯一不變的規則：升級的時候，前一關做好的功能要繼續能用。

Basic
純 HTML + CSS + JavaScript，單一檔案，靠 localStorage 記資料
Advance
前端不變 + 本地 Server（Node.js/Express 或 Python/Flask 自選）+ SQLite 或 JSON 檔儲存
Master
外部激勵語 API + 把後端功能包裝成 MCP Server，讓 Bob 能當工具呼叫
不變的東西
升級到下一關時，前面關卡做出來的功能都要繼續正常運作
準備好了嗎

打開 Bob，從 Basic 的第一個 Prompt 開始。

15 分鐘看到第一版能動的東西，剩下的時間，看你能陪 Bob 走到哪一關。
